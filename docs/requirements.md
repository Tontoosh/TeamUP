## Бизнес дүрмийн гол баталгаа

- **BR-01–02:** эзэмшигч/гишүүний эрхийг төсөл тус бүрд сервер шалгана.
  Админ эрхийг ердийн бүртгэл болон профайлын засвараар өгөхгүй.
- **BR-03–06:** өөрийн/гишүүн болсон төсөл, давхар pending/info хүсэлт, хаалттай
  элсэлт, блоктой хэрэглэгчийн хүсэлтийг хориглоно. Зөвшөөрөх үед орон тоо,
  үүрэг, хэрэглэгчийн эрхийг дахин шалгана. Шийдвэр ба гишүүнчлэл атомик.
- **BR-07–08:** шаардлагатай талбар, ур чадвар, холбоос, хугацаа, багийн хэмжээ
  сервер дээр шалгагдана. Сонголтот профайлын талбарыг цэвэрлэж болно.
- **BR-09–10:** мэдэгдлийг үндсэн өөрчлөлттэй ижил transaction-д хадгална.
  Клиент polling-оор татах тул хүргэлтийн саатал үндсэн үйлдлийг давхардуулахгүй.
- **BR-11:** админы шийдвэр болон лавлах импорт аудиттай.
- **BR-12:** хайлтын кэш хэрэглэгчээр тусгаарлагдсан; өгөгдөл, блок, эрхийн
  өөрчлөлтөөр хүчингүй болно. Хувийн API хариуд HTTP `Cache-Control: no-store`.

## Баталгаажуулалтын хүрээ

- TypeScript + Vite production build, код файл бүр ≤300 мөр.
- Интеграцийн тест: эрх, бүртгэл, токен, хүсэлтийн төлөв, зэрэгцээ зөвшөөрөл,
  багтаамж, архив, хавсралт, блок, мэдэгдэл, кэш, аудит, CSV-ийн хязгаар/rollback.
- 5,000 мөр импорт, 10,000 мөр экспортын SQLite дотоод хугацаа тестэд гарна.
  Энэ нь NFR-06/07-ын production сүлжээний баталгаажуулалт биш.
- Browser-ын харагдац, SMTP/Google үйлчилгээ, SQL Server холболтыг амьд орчинд
  шалгаагүй. Sandbox порт нээхийг хориглосон.
- NFR-01–09-ийн production ачааллын туршилт, ялангуяа 100,000 хэрэглэгч,
  50,000 төслийн хайлт тусдаа шаардлагатай. Их өгөгдөлд SQL хайлт/хуудаслалт
  руу шилжүүлж, сервер/сүлжээ/давталтын нөхцөлийг бүртгэн хэмжинэ.
