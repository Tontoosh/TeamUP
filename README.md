утгыг хадгалахгүй; тестийн SQL жагсаалтыг бодит өгөгдлийн сан дээр бүхэлд нь ажиллуулахгүй.

Орчны шалгалт: SQL Server холболт `Cannot generate SSPI context` алдаатай;

энэ session-ээс named pipe-д хандах эрхгүй тул контейнер/LAN шалгалт хийгдээгүй.

# Хамтдаа · TeamUp

## Windows дээрх одоогийн тохиргоо

Энэ компьютер дээр `tontooshko` серверийн `TeamUpDB` санд Windows Authentication-аар холбогдоно.
`start-teamup.cmd` файлыг нээж ажиллуулна. Дэлгэрэнгүй заавар: `WINDOWS-SETUP.md`.
Холболтыг зөвхөн шалгах: `npm run db:check`. Одоогийн `.env` нь demo өгөгдөл үүсгэхгүй, нэвтрэлт алгасахгүй.

Доорх SQLite заавар нь `.env.example`-ээс шинээр тохируулах хувилбар юм.

Оюутнуудын стартап хамтын ажиллагааны платформ. Эх шаардлага:
`/home/tontooshko/Desktop/hugjuulelt/fcsa312_hw/assignment1.pdf`.
Монгол интерфейс, PDF-ийн хар хөх/оюу ногоон прототип, гар утасны зохиомжтой.

## Ажиллуулах

Node.js **22.13+** шаардлагатай. Төслийн хавтсаас:

```bash
cd /home/tontooshko/webs/teamup
npm install
cp .env.example .env
npm run dev
```

Веб: **http://localhost:5173**. API: **http://localhost:3001/api/health**.
Vite `/api` хүсэлтийг Node сервер рүү дамжуулна. Хөгжүүлэлтийн хоёр серверийг
`Ctrl+C` дарж зогсооно. `.env` өөрчилбөл дахин асаана.

Production build-ийг дотоодод ажиллуулах:

```bash
npm run build
npm start
```

Дараа нь **http://localhost:3001** нээнэ. Node сервер `dist/` болон API-г хамт үйлчилнэ.
Production дээр `.env`-ийн `APP_URL`-ийг бодит URL болгоно.

## Нэвтрэлтийг түр алгасах

`AUTH_BYPASS=true` гэж тусгайлан тохируулсан дотоод SQLite горимд нэвтрэлт **түр алгасагдана**. `npm run dev`
ажиллуулаад сайт нээхэд жишээ оюутнаар шууд орно. Гадаад SQL Server холбох
шаардлагагүй; жишээ өгөгдөл дотоод SQLite-д автоматаар үүснэ.

Баруун дээд талын **«Туршилт · Оюутан / Эзэмшигч / Админ»** сонголтоор
өөр өөр хэрэглэгчийн дэлгэцийг нууц үг оруулахгүй шалгана. Нэвтрэх/бүртгүүлэх
хуудасны хуучин холбоосууд апп руу шууд шилжинэ.

Жинхэнэ нэвтрэлтийг буцаахдаа `.env`-д `AUTH_BYPASS=false` тохируулаад
серверээ дахин асаана. Түр горим нь `NODE_ENV=production` эсвэл
`DB_DRIVER=mssql` үед ажиллахгүй. Доорх имэйл/нууц үгийн бүртгэлүүдийг
нэвтрэлтийг буцааж идэвхжүүлсний дараа ашиглана.

Энэ ажлын sandbox npm сүлжээ болон localhost порт нээхийг хориглосон.
Иймээс тухайн машинд байсан сангуудыг `node_modules` дотор холбоод build, тест хийсэн.
Өөр машинд кодоо зөөхдөө `node_modules`-ийг хуулахгүй, `npm install` ажиллуулна.

## Өгөгдлийн сан

Анхны тохиргоо **SQLite**: `data/teamup.db`. Дахин асаахад өгөгдөл хадгалагдана.
Файлууд `data/uploads/` дотор; шууд public URL-аар үйлчлэхгүй. Хүснэгтүүд гадаад
түлхүүртэй, гишүүнчлэл давхцахгүй. Хүсэлтийн шийдвэр, багийн гишүүнчлэл, үүрэг,
мэдэгдлийг нэг transaction-д хадгална.

PDF-д сонгосон **Microsoft SQL Server**-ийг ашиглахын тулд сервер дээр `teamup`
өгөгдлийн сан үүсгээд `.env`-д:

```dotenv
DB_DRIVER=mssql
SQL_SERVER=localhost
SQL_PORT=1433
SQL_DATABASE=teamup
SQL_USER=sa
SQL_PASSWORD=your-password
SQL_TRUST_CERTIFICATE=true
```

`mssql` optional dependency суусан байх ёстой (`npm install mssql`). Апп эхлэхэд
`server/db/schema.js`-ээс хүснэгт/индексүүд автоматаар үүснэ. SQL Server дээр
`SERIALIZABLE` transaction ашиглана. Нууц үг, холболтын мэдээллийг Git-д оруулахгүй.
SQL Server энэ орчинд ажиллаагүй тул уг холболтыг амьд сервер дээр шалгаагүй.

## Имэйл, Google, файлын тохиргоо

SMTP тохируулаагүй үед баталгаажуулах/сэргээх холбоос **серверийн терминалд** гарна.
Бодит имэйл илгээхийн тулд `nodemailer` суулгаад `.env.example`-ийн `SMTP_*`,
`MAIL_FROM`, `APP_URL`-ийг бөглөнө. Холбоос 1 цаг хүчинтэй, нэг удаа ашиглагдана.

Google OAuth ашиглах бол `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` тохируулна.
Google-ийн authorized redirect URI:
`http://localhost:5173/api/auth/google/callback` (production үед `APP_URL`-тай ижил).
Тохиргоо байхгүй үед Google товч идэвхгүй бөгөөд шалтгааныг харуулна.
SMTP болон Google-ийн бодит үйлчилгээг энэ орчинд туршаагүй.

Файлын хэмжээ/өргөтгөл: `UPLOAD_MAX_MB`, `UPLOAD_TYPES`. Анхны 10 MB нь
хөгжүүлэлтийн тохиргоо бөгөөд PDF-ийн тогтмол шаардлага гэж үзэхгүй.

## Кодын бүтэц ба шалгалт

```text
src/
  components/    Дахин ашиглах интерфейс, диалог, карт
  pages/         Хуудас бүрийн ажиллагаа
  styles/        Хэсэг тус бүрийн CSS, responsive загвар
  api.ts         HTTP харилцаа
  context.tsx    Хэрэглэгч, мэдэгдлийн төлөв
  types.ts       TypeScript төрлүүд
server/
  db/            SQLite / SQL Server adapter, schema, жишээ өгөгдөл
  routes/        Үүргээр тусгаарласан API
  auth.js        Session, эрхийн шалгалт
  password.js    Salt + scrypt нууц үгийн хэш
tests/           Express middleware-тай интеграцийн тест
scripts/         300 мөрийн хязгаар шалгах
docs/            PDF-ийн юзкейсийн уялдаа
```

```bash
npm test
npm run build
npm run check:lines
```

Node.js 22 болон 24 дээр CI тест, build ажиллана. Тест бүр тусдаа process болон
түр SQLite сантай; нэмэлт test-isolation сонголт, системийн ODBC суулгац шаардахгүй.

Browser шалгалт: эхлээд `npx playwright install chromium`, `npm run build`,
дараа нь `npm run test:browser`. Энэ шалгалт 4173 порт дээр түр сервер,
санах ойн SQLite ашиглах тул `.env` болон одоогийн өгөгдлийн санд өөрчлөлт оруулахгүй.
Нэвтрэх хуудасны шилжилт, хайлтын хүсэлтүүд, алдааны дараах дахин оролдлого,
утасны цэс болон гарах үйлдлийг шалгана.

**Нэг код файл 300 мөрөөс хэтрэхгүй.** Энэ дүрэм build-ийн нэг хэсэг.
Generated `dist/`, dependency `node_modules/`, runtime `data/` нь эх кодын
хязгаарын тооцоонд орохгүй. JSX, серверийн код, CSS-ийг уншихад ойлгомжтойгоор хуваасан.

Тестүүд localhost socket нээхгүйгээр Express-ийн middleware/router болон жинхэнэ
түр SQLite өгөгдлийн сангаар HTTP хүсэлт/хариуг шалгана. Browser-ын харагдац,
Google/SMTP, амьд SQL Server, PDF-ийн 100,000 хэрэглэгч/50,000 төслийн ачааллын
NFR-үүдийг баталгаажуулаагүй. Төсөл болон ердийн хамтрагчийн хайлт SQL дээр шүүж/хуудасладаг.
Төсөлд тохирох хүний онооны эрэмбэ бүх кандидатыг харьцуулдаг. 15 секундын хайлтын кэш
өөрчлөлт бүрт хүчингүй болж, хэрэглэгчийн эрхээр тусгаарлагдана.

Юзкейсийн дэлгэрэнгүй: [docs/requirements.md](docs/requirements.md).
